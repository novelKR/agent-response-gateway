# 네이티브 확장 아키텍처

[English](../extensions-design.md) | [한국어](extensions-design.md)

 gateway는 사용자가 명시적으로 설치한 신뢰된 네이티브 메타데이터 관측 확장을 지원한다. 이 설계는 모델 전송을 작은 Rust 코어에 남기고 패키지 관리와 프로세스 실행을 분리한다. 계정 Pool, 자격증명 플러그인과 동적 프로토콜 어댑터는 후속 확장이며 현재 관측 규격의 기능이 아니다.

<a id="decision-and-alternatives"></a>

## 선택한 방식과 대안

코드 구성에는 내부 Rust 모듈을, 선택 기능에는 별도 설치 실행 파일을 사용한다. Cargo feature는 빌드를 제어하며 사용자 설치 기능 자체가 아니다. 최초 공개 패키지 역할은 숫자형 메타데이터 관측이다. 자격증명을 전달하는 인터페이스를 열기 전에 설치, 권한 승인, 활성화, 실행 정체성 결합과 장애 처리를 검증한다.

별도 프로세스는 패키지의 독립적인 선택을 허용하고 Rust 내부 자료 배치를 플러그인 ABI로 노출하지 않는다. 이후 모든 기능을 코어와 독립적으로 갱신할 수 있다는 보장은 아니다. 새로운 전송 또는 보안 의미를 지원하려면 코어와 규격 버전도 바뀔 수 있다. 네이티브 동적 라이브러리, WASM 런타임, 원격 패키지 검색, hot reload와 공개 마켓플레이스는 구현하지 않았다. 실제 확장에서 필요한 인터페이스가 확인된 뒤 격리된 정책 실행을 검토한다.

설치형 기능 하나가 여러 내부 모듈을 포함할 수 있다. 후속 계정 Pool도 인증, 갱신, 한도와 스케줄링을 사용자에게 각각 설치하게 할 필요는 없다. 서로 밀접한 자격증명 소유권은 하나의 검토된 수명 관리 아래 둔다.

<a id="core-and-extension-responsibilities"></a>

## 코어와 확장의 책임

```text
Consumer / agent
    |
    | Responses HTTP
    v
Gateway core ---------------------------------> Provider
    |  authentication, admission, transport       HTTPS / SSE
    |  capacity, cancellation, no implicit retry
    |
    +-- bounded metadata queue (no model bodies)
            |
       Extension supervisor
            |  private socket-backed stdin/stdout
            v
       Trusted observer executable
            |
       Per-package private state
```

로컬 인증, 경로·지원 기능 허용 판정, 공급자 목적지, 자격증명 사용, 본문 크기 제한, 스트리밍, 취소와 재시도 정책의 최종 통제권은 코어에 남는다. 관측 확장은 두 번째 모델 프록시가 아니다. 이 규격으로 도구 호출, 경로 변경, 응답 수정이나 자격증명 획득을 요청할 수 없다.

관리자는 숫자형 HTTP 상태와 응답 헤더가 준비되기까지의 경과 시간만 전달한다. 상태 검사와 인증 실패도 포함하지만 URL, 모델·경로 이름, 요청 ID, 헤더, 본문, 토큰 사용량과 도구 결과는 제외한다. HTTP 200 관측은 모델이 성공적으로 완료되었다는 증거가 아니며, 헤더 시간은 전체 응답 시간이 아니다. 관측은 최선형 전달이며 과금 자료나 영속적인 감사 원장이 아니다.

소비자 애플리케이션은 계속 도구 실행, 승인, 대화 이력과 실행 결과 대조를 소유한다. 관측 상태는 Responses 저장, 응답 조회, 원격 compact, 백그라운드 실행이나 계정에 결합된 재개를 구현하지 않는다. [내장 계약](embedded-design.md)과 [연속성 계약](continuity.md)을 함께 참조한다.

<a id="package-and-permission-contract"></a>

## 패키지와 권한 계약

오프라인 관리자는 압축파일이나 설치 스크립트가 아닌 단일 계층 디렉터리를 읽는다. 신뢰한 경로로 받은 정확한 명세 다이제스트, 전체 파일 목록과 각 파일의 다이제스트를 검사한다. 정규 패키지는 `gateway-extension-package/v1`, 활성화는 `gateway-extension-lock/v1`을 사용한다. 알 수 없는 필드, 미지원 역할, 중복 정체성, 비정규 JSON, 잘못된 대상, 심볼릭 링크와 하드링크된 패키지 파일을 거부한다.

패키지 준비 시 명시적으로 선택한 컴파일 입력만 하드링크를 허용한다. 해당 바이트를 새로운 패키지 inode로 복사한다. 설치와 런타임 검사는 계속 하드링크를 거부한다. 어떤 검사 명령도 패키지 코드나 셸을 실행하거나, 개인 자격증명을 검색하거나, 공급자에 접속하지 않는다.

요청 권한과 승인 권한은 별도 기록이다. 현재 버전에서는 `observe_http_metadata`와 `write_private_state`가 정확히 필요하며, 일부만 승인하거나 권한을 추가하면 실패한다. 승인 기록은 gateway 인터페이스 사용과 네이티브 실행을 허가한다. 임의의 시스템 호출을 제한하지는 않는다. 관리자는 활성화 쓰기를 직렬화하고 범위를 검사한 세대를 증가시킨 뒤 비공개 잠금 파일을 원자적으로 교체한다.

다이제스트가 결합하는 것은 바이트이지 배포자 정체성이 아니다. 서명 검사, 신뢰 루트 배포와 원격 갱신은 별도 구현이 필요하다. 정확한 버전에 맞는 패키지 출처와 프로젝트·제3자 고지를 유지해야 하며, 다이제스트 일치가 라이선스 검토를 대체하지 않는다. [설치 안내](extensions.md)를 참조한다.

<a id="process-lifecycle-and-failure-policy"></a>

## 프로세스 수명과 장애 정책

`--extensions-lock`이 없으면 확장 저장소를 읽지 않고 관측 프로세스도 시작하지 않는다. 지정하면 `check-config`와 `manifest`는 코드를 실행하지 않고 설치된 바이트를 확인한다. `serve`는 저장소의 독점 런타임 소유권을 얻고 실행 파일 무결성을 다시 확인한 뒤, 정확한 절대 경로의 실행 파일을 빈 상속 환경, 비공개 작업 디렉터리와 소켓 기반 표준 입출력으로 실행한다. 자식의 표준 오류는 버리며 신뢰된 진단으로 전달하지 않는다.

시작 시 gateway 준비 통지 전에 선언된 규격의 초기 연결 확인이 필요하다. 요청한 관측 확장 중 하나라도 시작에 실패하면 해당 선택형 실행을 거부하고 이미 시작한 직접 자식도 정리한다. 준비 완료 후에는 잘못된 응답, 종료 또는 제한 시간 실패가 발생한 관측 확장만 중지하며 일반 모델 경로를 비활성화하지 않는다. 관측 확장 자동 재시작, 관측 재전달과 모델 요청 재시도는 없다. 유휴 자식의 종료는 즉시가 아니라 다음 관측 또는 종료 과정에서 확인할 수 있다.

실행 중 프로세스는 시작할 때 읽은 활성화 스냅샷을 사용한다. 실행 중 활성화·비활성화·버전 선택은 다음 시작에만 적용된다. 관측 확장을 중지하려면 gateway를 중지한 뒤 검토한 잠금 파일로 다시 시작한다. 저장소당 런타임 소유자는 하나다. 관리 잠금은 별도이므로 실행 중에도 다음 시작의 변경을 준비할 수 있다.

종료 시 모든 관측 작업자에게 중지를 알리고 전달을 멈춘 뒤, 소유한 직접 자식을 종료하고 회수한다. 대기 중 관측은 버릴 수 있다. 규격 입출력 제한 시간이 중단 불가능한 커널 대기나 후손 프로세스 트리까지 제한하지는 않는다. 신뢰된 확장도 데몬화하거나 후손을 생성해서는 안 되며, 소비자 호스트는 외부 프로세스 제한 시간을 책임진다. gateway의 강제 종료와 적대적 네이티브 코드에 대한 프로세스 트리 격리는 보장하지 않는다.

<a id="observer-messages-and-limits"></a>

## 관측 메시지와 제한

```json
{"type":"ready","protocol":"gateway-observer/v1"}
{"type":"http","sequence":1,"status":200,"headers_ms":8}
{"type":"ack","sequence":1}
```

각 줄은 별도의 줄바꿈으로 끝나는 UTF-8 JSON 메시지이며, 자식의 준비 통지, 호스트의 관측, 자식의 확인 순서다. 순번은 프로세스마다 1부터 시작하고 확인 순번이 정확히 일치해야 한다. 알 수 없는 메시지 종류와 필드는 실패하며 자격증명과 역방향 콜백은 지원하지 않는다.

| 자원 | 구현된 제한 |
|---|---|
| 활성 관측 확장 | 4개 |
| 관측 확장별 큐 | 관측 64개, 포화·연결 종료 시 기다리지 않고 버림 |
| 줄바꿈을 포함한 응답 프레임 | 4,096바이트 |
| 시작 연결 확인 | 확장마다 3초, 순차 시작 |
| 관측 쓰기와 확인 | 하나의 공통 1초 제한 시간 |
| 유휴 관리자 확인 간격 | 50밀리초 |
| 패키지 또는 활성화 JSON | 65,536바이트 |
| 실행 파일 / 각 고지 파일 | 128 MiB / 256 KiB |
| 명세에 나열한 파일 | 명세 파일을 제외하고 2–8개 |

프레임 제한 시간에는 부분 입력과 전체 쓰기·읽기 교환이 포함된다. 상대가 조금씩 바이트를 보내 제한 시간을 무한히 늘릴 수 없다. 큐 제한은 네이티브 코드의 OS 메모리·CPU·네트워크 할당량이 아니다. 관측 확장이 늘면 전체 시작 시간과 자원 비용도 증가한다. 예제는 카운터만 저장하며 HTTP 경로는 그 디스크 쓰기를 기다리지 않는다.

<a id="trust-and-execution-identity"></a>

## 신뢰와 실행 정체성

네이티브 코드는 신뢰한 코드이지 OS 샌드박스가 아니다. 빈 상속 환경과 좁은 메시지는 우발적 노출을 줄이지만, 실행 파일의 사용자 파일 읽기, 네트워크 연결이나 같은 사용자 프로세스 공격을 막지 못한다. 권한 선언으로 이런 금지를 강제할 수 없다. 의도한 비특권 사용자로 실행하고 저장소 상위 경로를 다른 사용자의 변경으로부터 보호하며, 이 로더를 같은 사용자의 적대적 변경에 대한 방어로 취급하지 않는다. Windows 네이티브 실행은 동등한 파일·잠금·IPC 계약을 구현하기 전까지 명시적으로 실패한다. 확장 없는 gateway는 기존 대상에서 계속 사용할 수 있다.

선택형 실행은 `gateway-extended-manifest/v1`과 `gateway-extended-ready/v1`을 사용한다. `execution_sha256`은 기본 manifest와 확장 구성, 즉 절대 저장소 위치, 활성화 세대, 정확한 패키지 명세·다이제스트와 승인 권한을 결합한다. 가변 카운터 파일은 제외한다. 기본 `configuration_sha256`은 계속 gateway 구성만 나타낸다.

이 결합 다이제스트는 gateway 실행 파일을 해시하거나 배포자를 증명하지 않는다. 소비자 호스트가 코어 바이너리를 따로 검증하고 두 정체성을 함께 결합해야 한다. 작업을 시작하기 전에 확장 스키마를 확인하고 오프라인 `execution_sha256`을 준비 통지와 비교한다. 구형 소비자는 미지원 확장 스키마를 거부해야 하며, 기존 구성 필드만 확인하고 활성 코드를 무시해서는 안 된다.

기존 호스트 연속성 기록을 자동 이행하는 기능은 아니다. 관측 확장을 사용하는 호스트는 기존 검증된 실행 연결과 함께 확장 실행 정체성도 보관해야 한다. 후속 자격증명 확장은 명시적으로 버전 관리한 연속성 변경이 필요하며, 환경변수 이름이나 불투명한 핸들만으로 자격증명 소유권을 증명할 수 없다.

<a id="codex-pool-extension-proposal"></a>

## Codex Pool 확장 제안

```text
Future account-pool request (proposal; not observer/v1)

Host binds route + account realm + policy revision
    -> Core admits request and validates existing session binding
    -> Pool proposes an eligible account and credential lease
    -> Core validates destination, entitlement, binding and attempt budget
    -> Core sends one qualified model request directly to the provider
    -> Core reports a classified outcome; credential owner releases the lease

Unknown acceptance / partial output
    -> no transparent replay
    -> explicit host reconciliation or a new portable-context thread
```

계정 Pool은 별도로 제안된 역할이며 관측 명세에 권한을 하나 더 적어 활성화할 수 있는 기능이 아니다. 브로커에는 요청이 소유하는 자격증명 임대, 모델·워크스페이스 적격성, 한도 근거와 계정에 결합된 세션이 필요하다. 코어 전송은 Pool 프로세스 밖에 남겨야 하며 모든 SSE 조각을 스케줄러로 통과시키지 않는다.

인증 권한별 갱신은 하나의 권위 있는 소유자가 담당해야 한다. 세대를 확인하는 쓰기로 삭제·교체·재인증한 계정과 늦게 도착한 한도·건강 결과를 구분해야 한다. 알 수 없거나 오래된 한도는 사용량 0이 아니다. 공유 제한은 공유 상태로 유지하며, 다른 자격증명 선택이 워크스페이스나 공급자의 제한을 우회할 권한을 주지 않는다.

새 작업의 계정 선택과 이미 시작한 대화의 이동은 다른 작업이다. 암호화된 reasoning, compaction 자료나 공급자 내부 식별자를 계정 사이에서 옮길 수 있다고 가정하지 않는다. 재시작 후 연결을 잃거나 만료되었다면 명시적인 호스트 전이 또는 검증된 이식 가능 문맥으로 만든 새 스레드가 필요하다. 토큰 개정과 계정·워크스페이스 원점은 별개이며, 호환성을 위해 기존 검사를 재해석하지 말고 새로운 검토 스키마를 정해야 한다.

Pool 장애는 모델이 아무 작업도 하지 않았다는 증거가 아니다. 재시도 없는 기본값을 유지하고 전송 전 실패, 확인된 거부, 수락 여부 불확실성을 명시적으로 분류한다. 일부 SSE, 공개된 도구 출력과 취소는 투명한 재실행의 근거가 될 수 없다. 후속 장애 전환에는 호스트와 조율한 시도 예산과 전체 제한 시간이 필요하다.

토큰·스키마 이행은 실행 파일 롤백과 분리한다. 인증 권한 하나에 갱신 주체를 둘 이상 실행하거나 구형 바이너리로 돌아가기 위해 오래된 자격증명을 복원하지 않는다. 사용자의 일반 Codex 로그인을 자동으로 가져오지 않는다. 자격증명·연속성 계약을 검토하고 별도 시험하기 전까지 이런 요구사항은 미구현이다.

## 검증과 후속 확장

[관리자](../../scripts/extension_manager.py), [Rust 계약](../../src/extensions/mod.rs), [프로세스 관리자](../../src/extensions/runtime.rs), [네이티브 통합 검사](../../scripts/extension_smoke.py)가 구현 근거다. 통합 검사는 합성 loopback 트래픽으로 실제 실행 파일을 확인한다. 성공이 실제 공급자 검증이나 임의의 제3자 패키지 실행 허가를 의미하지는 않는다.

최초 역할은 좁게 유지한다. 입증된 필요가 있을 때만 계약을 확장한다. Pool에는 자격증명·연속성 검토가, 외부 전송 어댑터에는 독립적인 스트리밍·역압·취소 검증이, 불신 코드에는 실제 격리가 필요하다. 확장 SDK, 서명, 원격 검색, Windows 프로세스 관리와 관리 UI는 별도 작업이다. 확장을 배포할 때 제3자 권리와 해당 소스 제공 요구를 명시적으로 유지하며, 프로세스 분리는 라이선스 판단 자체가 아니다.
