# 호스트 애플리케이션에 게이트웨이 내장하기

[English](../embedded-design.md) | [한국어](embedded-design.md)

호스트 애플리케이션은 게이트웨이를 자식 프로세스로 시작하고 관리한다.
에이전트를 시작하기 전에 실행 파일과 설정을 확인하고, 자격 증명을 분리해
전달하며 종료와 복구를 제어한다.

<a id="cli와-manifest-제안"></a>
<a id="configuration-manifest"></a>
<a id="proposed-cli-and-manifest"></a>

## 설정 명세

`agent-response-gateway manifest --config <path>`는 설정을 검사하고 stdout에
JSON 객체 하나를 출력한다. 수신 서버를 시작하거나 자격 증명 값을 읽거나
공급자에 접속하지 않는다. 출력 형식은 `gateway-embedded-manifest/v1`이며
프로세스 수명 계약 `host-supervised-process/v1`을 명시한다.

설정 명세에는 다음을 포함한다.

- 패키지 이름·버전과 Responses 클라이언트 API.
- 수신 주소, 선택적 소스 URL, 로컬 토큰의 환경 변수 참조와 한도.
- 설정된 모든 공급자 자격 증명의 환경 변수 참조. 사용하지 않는 공급자도
  서버 시작 시 자격 증명을 검사하므로 포함한다.
- 별칭순 경로 목록: 공급자, 확정된 주소, 업스트림 모델·API, 인증 방식,
  자격 증명 참조, 선택적 Messages 버전, 어댑터·프로필 버전, 지원 기능,
  컨텍스트·출력 한도와 시험한 Codex 버전.
- 정규화한 설정의 SHA-256인 `configuration_sha256`.

생략된 선택값은 null이다. 해시는 키를 재귀적으로 정렬하고 공백 없는 구분자를
사용한 UTF-8 JSON으로 계산하며 끝 줄바꿈은 포함하지 않는다. 경로 순서는
일정하다. 값은 정수·불리언·문자열·객체·배열·null이며 부동소수점은 사용하지
않는다. 의미가 같은 기본값과 URL 표기는 같은 해시로 정규화한다.

명세에는 설정 참조만 담고 비밀 값, 프롬프트나 이력은 넣지 않는다.
실제 배포 주소와 식별자는 비공개로 보관한다. 해시는 설정의 일치 여부를
검사하며 실행 파일 무결성은 별도로 확인한다. `check-config`도 같은 검사
규칙을 사용하지만 이 명세를 출력하지는 않는다.

## 준비 통지

`serve`의 첫 stdout 줄은 실행 중인 자식 프로세스를 설명한다.

| 필드 | 의미 |
|---|---|
| `event` | ready |
| `address` | 실제로 바인딩한 숫자 루프백 주소 |
| `base_url` | Responses 클라이언트 기본 URL |
| `version` | 게이트웨이 버전 |
| `schema` | `gateway-ready/v1` |
| `manifest_schema` | `gateway-embedded-manifest/v1` |
| `configuration_sha256` | 수신 서버와 라우터가 사용한 설정의 해시 |

이 값을 앞서 확인한 실행 파일과 설정 명세에 대조한다. 설정 해시나 주소가
예상과 다르면 시작을 중단해야 한다. 준비 통지는 로컬 기동을 확인하며
공급자 자격 증명이나 모델 가용성을 검증하지는 않는다.

<a id="process-lifecycle"></a>

## 프로세스 수명

1. 고정 실행 파일, 소스, 고지와 호환성 기록을 확인한다.
   비공개 설정 사본을 만들고 설정 명세를 조회한다.
2. 인스턴스 전용 로컬 토큰을 생성한다. 게이트웨이에는 필요한 공급자 자격
   증명을, 에이전트에는 게이트웨이 토큰만 전달한다. 자식 환경을 명시적으로
   구성하고 개인 에이전트 설정과 분리한다.
3. 확인한 게이트웨이 실행 파일을 시작한다. 기동 제한 시간 안에 크기가 제한된
   준비 통지 한 줄을 읽고 보고값을 검사한다. Stderr는 별도로 처리한다.
   무관한 프로세스에 연결하거나 고정 포트를 사용할 수 있다고 가정하지 않는다.
4. 준비를 확인한 뒤 에이전트를 시작한다. Codex는 전용 비공개 홈, 지원되는
   모델·목록 프로필, Responses API와 보고된 기본 URL을 사용한다.
   대체 경로·재시도를 끄고 실제 모델과 공급자를 확인한다.
5. 종료 시에는 새 작업 중단, 진행 중인 요청의 중단 또는 완료 처리,
   에이전트의 모델 연결 종료, 게이트웨이 종료 순서를 따른다. Unix의 SIGTERM/SIGINT와
   Windows의 CTRL_C_EVENT/CTRL_BREAK_EVENT는 설정된 유예 시간을 사용한다.
   Windows에서는 CREATE_NEW_PROCESS_GROUP으로 자식을 만들고 그 그룹에만
   CTRL_BREAK_EVENT를 보낸다. 호스트가 최종 제한 시간을 적용하고 자식을 회수한다.
   TerminateProcess는 강제 정리이며 정상 종료가 아니다.
6. 시작에 실패하면 시작한 자식 프로세스와 임시 자격 증명을 정리한다.
   예상치 못한 종료로 영향을 받은 작업은 실패 또는 결과 불명으로 기록한다.
   모델 요청을 자동 재시작하거나 다른 경로를 선택하지 않는다.

HTTP 종료·관리·설정 명세 엔드포인트는 없다. 프로세스 제어는 부모 애플리케이션이 담당한다.

## 인증과 접근

로컬 Bearer 토큰 하나로 해당 게이트웨이 인스턴스에 설정된 모든 모델 별칭에
접근할 수 있다. 더 적은 별칭이 필요하면 인스턴스 설정을 제한한다.
이 토큰은 파일 접근, 도구 실행, 승인이나 테넌트 식별 권한을 부여하지 않는다.

접속 주소는 숫자 루프백을 사용한다. 업스트림 URL은 숫자 루프백 모의 서버를
제외하면 HTTPS가 필수다. 공급자 인증을 명시하고, 각 요청은 환경의 프록시를
상속하거나 리디렉션·대체 경로를 사용하지 않고 업스트림에 한 번만 전송한다.
애플리케이션의 도구 권한과 승인 규칙은 그대로 적용된다.

## 재개와 호환성

명세를 사용하는 호스트는 지원되는 정확한 스키마를 요구해야 한다.
이력을 다시 사용하기 전에 [연속성 계약](continuity.md)에 따라 설정,
경로·프로필, 실행 파일과 자격 증명의 변경 여부를 검사한다.

환경 변수 이름만으로 현재 자격 증명의 세대를 식별할 수는 없다.
호스트가 자격 증명 관리자에게서 해당 식별 정보를 받아야 한다.
필수 연결 조건이 달라졌다면 명시적으로 전환하거나 새 맥락으로 시작한다.

게이트웨이는 세션 상태를 영속 저장하지 않는다. 에이전트 런타임 선택과
저장된 이력의 호환성은 호스트가 책임진다.

## 검증과 복구

테스트는 설정 정규화, 오프라인 조회, 준비 통지 일치, 주소 바인딩 실패,
기동 시간 초과와 활성 응답이 있는 상태의 제한된 종료를 검사한다.
호스트 시험은 해시를 독립적으로 다시 계산하고 자식의 자격 증명·설정 분리를
확인한다. 준비 방법은 [Codex 시험 안내](../../tests/codex/README.ko.md)를 따른다.

복구할 때는 검증된 호스트·실행 파일·설정 조합과 호환 이력을 복원한다.
이 명세를 요구하는 호스트는 명세를 제공하지 못하는 바이너리를 거부해야 한다.
실제 공급자와 애플리케이션의 동작은 사용할 배포 환경에서 따로 시험해야 한다.

## Rust 인터페이스

`Config::manifest()`는 불변 EmbeddedManifest를 반환한다.
라우터와 수신 서버를 만드는 동일한 Config의 configuration_sha256을 준비 통지에도
사용한다. 직렬화 시 Secrets를 읽지 않는다. 알려진 미지원 기능은 생략된 기본값으로 정규화한다.
