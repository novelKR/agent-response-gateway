# 이력·압축·재개

[English](../continuity-design.md) | [한국어](continuity-design.md)

Codex와 호스트가 대화 이력과 복구 기록을 보관한다. 게이트웨이는 상태를
저장하지 않는 모델 요청을 처리하며, 응답 저장이나 원격 압축 엔드포인트를 제공하지 않는다.

## 로컬 압축

공급자 프로필이 원격 압축을 지원하지 않는다고 선언하면 고정 Codex는 로컬
압축을 사용한다. 일반 `/v1/responses` 엔드포인트로 요약 요청을 보내고
자신의 이력을 갱신한다. 호스트가 `thread/compact/start`를 호출하고
다음 요청을 시작할 시점을 결정한다.

이 경로는 모의 공급자 시험으로 검증한다. 실제 모델의 요약 품질과 해당
요약으로 작업을 이어갈 수 있는지는 사용할 작업에 맞춰 검증해야 한다.

<a id="responsibilities-and-interfaces"></a>

## 책임과 인터페이스

| 담당 | 책임 |
|---|---|
| Codex | 대화 이력, 로컬 압축, 도구 결과 맥락과 재개 제어 |
| 호스트 런타임 | 검증된 실행 파일·설정, 실행 연결 정보, 취소·복구·명시적 모델 변경 |
| 게이트웨이 | 요청별 고정 경로, 공급자 자격 증명, 프로토콜 변환과 상태 저장 없는 오류 처리 |
| 애플리케이션 워크플로 | 작업 체크포인트, 사용자 승인과 업무 판단 |

`thread/start`, `thread/resume`, `thread/compact/start`, `turn/start`,
`turn/interrupt`를 사용한다. 게이트웨이는 저장된 응답 참조와 원격 압축
요청을 지원하지 않는다.

## 실행 연결 정보와 복구 기록

실행 연결 정보는 함께 사용할 수 있는 런타임, 경로, 자격 증명과 이력의
정확한 조합을 기록한다. 호스트는 비공개 `gateway-run-binding/v1` 기록에
다음을 보관한다.

- Codex 버전, 실행 파일 해시와 상태 호환성.
- 게이트웨이 버전·해시와 유효 설정의 해시.
- 공급자, 실제 모델, API, 지원 기능 프로필과 어댑터 버전.
- 원문 키를 제외한 자격 증명 영역과 세대 참조.
- 대화 식별자, 비공개 이력 참조, 마지막 완료 요청과 복구 상태.
- 컨텍스트·출력 한도, 압축 정책과 요청·재시도 예산.

전환이 완료되면 새 기록을 원자적으로 저장하고 이전의 호환 기록·이력을
복구용으로 보관한다. 재개 전에는 현재 실행 파일, 설정과 자격 증명 관리자를
기준으로 연결 정보를 확인한다. 환경 변수 이름이 같아도 자격 증명이
변하지 않았다는 뜻은 아니다. 새 설정으로 과거 별칭을 임의로 해석하지 않고
확인되지 않은 연결 정보를 거부한다.

<a id="supported-continuation-paths"></a>

## 지원하는 연속 실행 경로

1. **같은 프로세스·경로:** 현재의 전체 맥락과 도구 결과를 해당 경로가 지원하는
   상태 저장 없는 요청 형식으로 보낸다.
2. **로컬 압축:** Codex가 요약을 생성하고 이력을 교체한다.
   요약은 일반 내용이며 공급자가 암호화한 상태가 아니다.
3. **프로세스 재시작:** 호환 Codex 설정·이력과 기록된 실행 연결 정보를 복원한다.
   새 요청을 시작하기 전에 재개한 모델·공급자를 확인한다. 완료된 도구는 재실행하지 않는다.
4. **명시적 모델 변경:** 검증된 경로를 선택하고 이동 가능한 메시지·완료된 도구
   결과로 새 맥락을 시작한다. 생략한 불투명 상태와 새 연결 정보를 기록하고
   워크플로 체크포인트와 승인은 별도로 보존한다.

원격 압축을 요구하는 프로필은 이 로컬 압축 계약을 사용할 수 없다.
런타임을 바꿀 때는 선택한 Codex 버전의 실제 동작을 확인해야 한다.

## 불투명 상태와 결과 불명

불투명 공급자 상태는 암호화된 추론처럼 게이트웨이가 해석하지 않는 데이터다.
확인된 원본 연결 조건 안에서만 보존한다. 다른 프로토콜로의 재사용은 거부하며,
텍스트 요약이 서명되거나 암호화된 상태를 대체하지는 못한다.

취소 시험은 이벤트가 흐르는 스트림과 heartbeat 주석만 보내는 스트림을 모두
포함해야 한다. 제어 요청을 중단하면 시험 기준 시간 안에 업스트림 모델 연결도
닫혀야 한다.

요청을 보냈지만 응답을 확인할 수 없다면 결과를 Unknown으로 기록한다.
호스트가 예산 안에서 복구와 재시도를 결정하며 게이트웨이는 업스트림에 한 번만
전송한다. 도구 결과나 승인을 기다리는 동안에는 압축하지 않는다.
실행 검사와 저널 형식은 [연속성 계약](continuity.md)에 정의되어 있다.

## 검증과 복구

도구 결과 재입력, 압축, 재시작, 경로·프로필 불일치, 자격 증명 변경,
모델 전환, 취소와 결과 불명을 시험한다. 압축·재시작 뒤 필요한 맥락과 완료된
도구 결과가 유지되고, 도구가 중복 실행되거나 미승인 동작이 이어지지 않는지 확인한다.

연결 정보가 검증되지 않은 기록을 신뢰할 수 있는 이력으로 재개할 수는 없다.
검사된 이전 절차로 연결 정보를 확보하거나 새로 시작한다. 복구는 검증된
실행 파일·설정·이력 조합으로 수행하며, 호환되지 않는 새 상태를 이전 코드로
열지 않는다. 운영 전에 사용할 작업으로 모델 요약과 호스트 복구를 검증해야 한다.
